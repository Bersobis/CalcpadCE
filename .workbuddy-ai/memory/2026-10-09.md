# 2026-10-09

## Reworked the Live Editor as a from-scratch MathML/OMML math engine

Branch: `Experimental-Live-Editor-2` (was identical to `main` at the start).

### What was built

A dependency-free math rendering + WYSIWYG editing engine in
`Calcpad.Web/frontend/calcpad-frontend/src/math/`, replacing both prior attempts
(`Experimental-Live-Editor`). **No LaTeX, no MathLive** — the model is MathML, rendering is the
browser's native MathML Core, and Word interop is OMML.

Modules: `model.ts`, `grammar.ts`, `tokenizer.ts`, `parser.ts`, `printer.ts`, `serialize.ts`,
`xml.ts`, `omml.ts`, `caret.ts`, `insert.ts`, `hit-test.ts`, `history.ts`, `line-model.ts`,
`gate.ts`, `capability.ts`, `index.ts`.

Surface: `src/vue/components/CalcpadMathField.vue` (one expression) and `CalcpadLiveMath.vue`
(the worksheet as regions). Wired into the sidebar as a **Live math** tab via
`CalcpadApp.vue` + a new `onReplaceLine` host hook in
`services/message-bridge/base.ts`, implemented in `calcpad-web/src/main.ts`.

Docs: `docs/new-mathml-math-engine.md`, added to `mkdocs.yml`.

### Key design decisions (do not regress these)

- **AST stores canonical Calcpad glyphs, never a presentation form.** `*` is stored as `*`, not
  `·`. Presentation translation lives only in `serialize.ts` and `omml.ts`. This is what makes
  the printer an exact inverse.
- **Names split at the first `_` into a subscript** — that is how Calcpad renders variables, so
  `msub` comes from names and there is no `_` operator.
- **The editability gate is a fixed point check**: `parse → print → parse` must give the same
  tree. Anything else is shown as source and never rewritten.
- **An empty slot has no Calcpad spelling** → commit is refused; the printer emits nothing for
  it (`qx^`, not `qx^()`).
- **A commit that does not change the parse is dropped** (`sameMeaning`), so a no-op click never
  rewrites a line.
- **Units are not guessed.** Only the right-hand side of a `|` unit target renders upright;
  styling every unit *symbol* upright would mis-render `V`, `s`, `t`, `h`.
- **The editor/parser invariant is pinned**: `sameTree(tree, parse(print(tree)))` after every
  edit, for every palette structure. This is the test that catches component-level drift.

### Measured (Examples/, 249 files, 7729 expression lines)

71.2% of expression lines parse to a stable tree and open as fields (previous attempt: 59.6%).
Remaining 28.8% is SVG drawing calls (`line$(…)`), `#UI` input controls, and multi-assignment
lines — all safely declined as source.

## Fixed: `tauri dev` failed when the checkout path contains a space

Symptom: `beforeDevCommand` → `dev-frontend.ps1:85` → `Write-Error "dev-frontend: calcpad-web
build failed"`, whose body was the child powershell's stderr:
`Processing -File 'C:\Users\Admin\3D' failed because the file does not have a '.ps1' extension.`

Root cause: `Start-Watcher` launched the watcher with
`-ArgumentList …, '-File', "`"$LocalNpm`""`. The escaping in the source is correct (verified by
hexdump), but **Windows PowerShell's `Start-Process -ArgumentList` drops the quotes around an
array element**, so the absolute path reached the child unquoted and split at the space in
`C:\Users\Admin\3D Objects\…`. The watcher never started; `Wait-ForBuild` saw the process exit
and reported the *label* (`calcpad-web build`), which is why the message looked like a build
error. `origin/main` has the same bug — it is not a regression from the math engine work.

Note commit `6cc0f3b4` ("fix Tauri start if the path contains spaces") attempted this by *adding*
those quotes. It never worked; do not reintroduce it.

Fix: name the wrapper **relative** to the working directory that was already being set, so the
argument contains no space and needs no quoting:
`-ArgumentList …, '-File', '.\local-npm.ps1', …` with `-WorkingDirectory $ScriptDir`.
`-FilePath` and `-WorkingDirectory` are parameters, so their spaced values are safe; only the
command-line argument string was fragile. Verified the file parses with zero errors and the
resulting command line carries no spaced path.

`build-frontend.ps1` and the Tauri `before*Command` entries were checked and are already safe
(they use the call operator `& $LocalNpm`, which does not build a command-line string).

Not verified end-to-end here: `tauri dev` itself, since spawning the watcher is blocked in this
environment. The fix should be confirmed on a spaced path by running `tauri dev`.

## Applied the code-review findings for the math engine

Reviewed the editor adversarially first (probes, not inspection), then fixed. 70 tests pass,
`tsc` and `vue-tsc` clean, `vite build` succeeds.

### Correctness

- **P0 — the guard had a hole.** `emptySlotPaths` only found empty *containers*, so deleting the
  last character of a leaf left `mn('')`, which prints as nothing and was not flagged; `commit()`
  wrote `a = /2` into the document. Fixed in two places: an empty leaf is now a slot, and
  `commit()` runs `isCommittableText` (the engine's gate) rather than a weaker local rule.
- **The invariant is now checked, not argued.** `applyCharacter` refuses any keystroke whose
  printed text re-parses to a different tree. Incomplete text (`a + `) is still allowed — the
  commit gate keeps it out of the document.
- **`makeLeaf` is grammar-aware.** Operators become `mo` nodes, digits extend names, and
  characters that cannot begin a token (`_`, `,`, `.`, separators) are declined. Names go through
  the parser's own `nameToNode`, so `a_b` becomes the `msub` the parser builds.
- **Juxtaposition is a flat row, not left-nested.** This was the single biggest win: the editor
  and the parser now agree on product shape. Corpus went 71.2% → **76.5%** editable as a result.
- **Deletion works.** Backspace at offset 0 merges into the previous leaf; emptying a leaf in a
  row removes it; a two-branch structure collapses to the surviving branch (`1/` → `1`).
- Printer: a leading operator is a prefix, not a binary op (it was printed twice), and a
  malformed row falls back to concatenating children instead of silently dropping them.

### Performance

`CalcpadLiveMath` re-classified the whole document on every commit. `lineRegions` now takes an
injectable classify function and `LineModel` memoises per line text: **30 ms → 0.5 ms** per
commit on a 400-line worksheet.

### Usability and integration

Per-operation undo tags + `History.breakCoalescing()` (the session used to be one undo step);
clipboard (`Ctrl+C/X/V`, whole line — Calcpad text is the storage format so no interchange is
needed); `isComposing` guard for IME; caret drawn on focus as well as click; host→panel sync with
a dirty flag so a push cannot clobber an uncommitted edit. Capability probe is now Node-safe and
caches only positive results. Removed dead exports (`cloneNode`, `withChildren`, `parentOfPath`,
`countNodes`, `typeableCharacters`, `anchorIndex`, `caretTextIndex`, `containerAt`).

### Largest remaining opportunity

**Custom unit definitions (`.EUR = 1`) — 963 lines, the biggest declined bucket.** They are
declarations, not expressions; supporting them means teaching the tokenizer a leading dot. Not a
bug fix, so left out of this pass.

## Live editor: persistent palette + click-to-edit

Two UI changes requested after using it.

- **The palette is now always visible**, docked once above the worksheet in
  `CalcpadLiveMath.vue` and `position: sticky`, instead of appearing only on focus. It targets
  whichever equation is being edited and shows "Click an equation to edit it" when none is.
  Deliberately **not** repeated per equation — at sidebar width that wraps into a column beside
  every line, which is the mistake the previous attempt documented.
- **Click to edit** (new toggle, off by default): an idle field takes no caret, ignores the
  keyboard and is `tabindex="-1"`, so a 30-equation sheet is not 30 tab stops. Clicking promotes
  one field and the previous one commits on blur. This is the Mathcad/MathType model.
- `CalcpadMathField.vue` gained `showPalette`, `clickToEdit` and `active` props, and an
  `activate` event. `PALETTE_SYMBOLS` moved into `insert.ts` beside `STRUCTURES` so the field's
  palette and the panel's toolbar share one source.

### The ref trap — bitten twice now, so it is linted

Field instances are registered with a **stable per-line function ref** (`fieldRef(line)` memoised
in a Map). Two alternatives both fail invisibly:

- `ref="field"` inside `v-for` → Vue collects it into an **array**, which is truthy, so a guard
  passes and the call site throws "is not a function". This is what made every palette button dead
  in the previous attempt.
- `:ref="(x) => …"` → a **new function every render**, and Vue unsets a changed ref before setting
  it, so the unset (`null`) unregisters the field on every commit and the toolbar loses its
  target. I nearly shipped this one.

`tests/vue/template-refs.test.ts` fails the build on either, verified by reverting to the inline
arrow and watching it fail. `npm test` now runs both suites (**73 tests**).

## Bug: palette labels invisible, and the panel looked dead

Reported from a screenshot: the palette rendered as blank dark boxes, and nothing responded.

### Root cause 1 — an unpaired theme token (proven, not guessed)

`.cp-math-key` set `background: var(--vscode-button-secondaryBackground)` but `color: inherit`.
`inherit` resolves to the sidebar's `--vscode-foreground`:

| Theme | Colour on the button fill | Ratio |
| --- | --- | --- |
| light | `#616161` on `#5f6a79` | **1.13:1** — invisible |
| dark | `#d4d4d4` on `#3a3d41` | 7.36:1 — fine |

Light-only, which is why the screenshot (light theme) showed blank boxes and it read as a
missing-glyph problem. The correct token, `--vscode-button-secondaryForeground`, was already
paired with that background in `scripts/check-contrast.mjs:120` and used correctly by
`.reset-button` in the same stylesheet. I simply deviated.

**Fix:** the rule now lives once in `src/vue/styles/base.css` (the file both hosts import) with
the correct pairing, and the duplicated scoped copies were deleted — the duplication is how both
copies got the same defect. `tests/vue/component-css.test.ts` fails on an unpaired button
background or a `color: inherit` in a palette rule; verified by reintroducing the bug.

### Root cause 2 — no target, and no empty state

With an empty document the panel rendered one empty `<pre>` (invisible), so there was literally
nothing to click and every palette button was a silent no-op. Fixed:

- Palette buttons are `disabled` until an equation is being edited, so they read as inert.
- The hint explains what they act on.
- An explicit empty state replaces the blank panel.
- `registerField` now refreshes `activeField` when the active line re-registers, so a re-created
  region cannot leave the toolbar pointing at an unmounted instance.

`npm test` → **75 tests**, `vue-tsc` clean, `vite build` ok, `check-contrast.mjs` 173/0.
