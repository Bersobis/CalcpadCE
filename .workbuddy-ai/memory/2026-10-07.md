# 2026-10-07 — Live editor: reliability fix + graphical math editing

Branch: `Experimental-Live-Editor`. Work continued the in-progress rewrite that deleted the
duplicated TypeScript math stack (`calcpad-frontend/src/math/*`, MathLive components) and
replaced it with the server-driven `CalcpadLiveDisplay.vue`.

## Reliability fixes (`calcpad-web/src/live-display/`)

The old pane asked the server for **one line at a time**, sending a growing document prefix per
request. Three concrete defects:

1. **Stale dependent lines.** Only the changed lines were re-made, so editing `a = 5` → `a = 6`
   left `b = a + 1` showing the old result. Fixed by rendering the **whole document in one
   request** and mapping the result back to rows.
2. **Dead cache.** The render cache was written but never read (`cachedHtml` had no caller), and
   keyed by line text, which ignores the prefix that determines the output. Removed with the
   per-line design.
3. **Fragile line extraction.** `convertLine` read `#line-N` from a full-document convert. Now
   `CalcpadApiClient.convertLines()` renders once and `splitRenderedLines()` (exported, tested)
   splits the markup into one entry per source line; `null` where a line rendered nothing.

Also: `lineDiff.ts` deleted (obsolete); `sourceFilePath` now threaded through so `#include`
resolves; a non-blank line with no rendered markup shows its source in monospace instead of a
silent gap.

## Graphical editing

- New pure module `calcpad-frontend/src/text/math-palette.ts`: `PaletteAction` catalog of
  structures, functions, operators, relations and Greek, each `apply(line, selection)` →
  `{ text, selection }`. Wraps a selection (`a+b` → `sqrt(a+b)`), extends what is already there
  (`x` + caret → `x^()`), and keeps the caret in the right slot for two-slot structures.
- New `CalcpadMathPalette.vue`: searchable, collapsible button grid. Buttons cancel `mousedown`
  so the edited field keeps focus and its caret.
- `CalcpadLiveDisplay.vue`: the editor is now the whole-line field + the structure fields
  (matrix cells, function args) + the palette. Typing re-renders the row live (debounced 220 ms,
  `key: 'live:preview'`), so the typeset result is visible before commit. `lastField` tracks the
  palette's target so the palette's own search box can hold focus safely.
- Focus leaves the editor panel → commit; moving between its fields does not.

## Conventions worth keeping

- One render per document, not per line: `convert` with `includeLineAnchors: true` (positional
  arg 8) is what emits `id="line-N"`. `unwrap=true` does **not** work — it routes to
  `ConvertCodeToHtml` (the code view), not the typeset output.
- Pure logic goes in `calcpad-frontend` (has vitest), Vue wiring in `calcpad-web` (no vitest).
- `jsdom` added as a `calcpad-frontend` devDependency; DOM tests opt in per file with
  `// @vitest-environment jsdom` (the default env stays `node`).
- **Palette glyphs must be engine-supported.** `docs/quick-reference.md` "Operators" is the
  list: `! ^ / ÷ \ ⦼ * - + ≡ ≠ < > ≤ ≥ ∧ ∨ ∠ ⊕ = ←`. There is **no** `±` or bare `%`, and
  multiplication/subtraction are `*`/`-`, not `·`/`×`/`−` (those are display-side only). A test
  pins this so a button can never insert syntax the parser rejects.

## Verification

`tsc` clean; **35 tests pass** (20 palette + 6 split + 9 pre-existing); `vite build` clean
(1192 modules). Build to a scratch `--outDir` — emptying `dist/` trips the sandbox bulk-delete
guard.

## Still open

- `LIVE-EDITOR-*.md` and `docs/new-wysiwyg-equation-editor.md` still describe the removed
  MathLive design; they need a status update.
- No end-to-end run: needs the .NET server + a browser.

# 2026-10-07 (later) — MathML-native graphical editor

Added a **MathML-native** graphical equation editor to the live display. Explicitly *not*
MathLive and **no LaTeX anywhere**: the model, the rendering and the serialization are all
MathML. Opt-in, and it touches nothing outside the frontend.

## Core (`calcpad-frontend/src/mathml/`, pure + tested)

| File | Role |
|---|---|
| `ast.ts` | MathML AST (`mrow`/`mfrac`/`msqrt`/`mroot`/`msup`/`msub`/tokens) + path addressing |
| `serialize.ts` | AST → MathML; `serializeWithPaths` adds `data-path` so a click maps back to the tree |
| `parse.ts` | MathML → AST (DOMParser); unknown elements are kept, never dropped |
| `calcpad.ts` | Calcpad ⇄ MathML bridge + the **editability gate** |
| `caret.ts` | caret/selection model, navigation, insert/delete, structure building |

Key design points:

- **The editability gate is a fixed point on the *tree*, not the text.** `checkGraphicallyEditable`
  parses → writes back → re-parses and requires the two trees to match. Spacing may differ;
  a construct the bridge models imperfectly shows up as a different tree and the line falls
  back to the source editor. That is what makes "decline rather than corrupt" enforceable.
- **Anchors are canonical.** A `gap` between children coincides visually with the end of the
  child before it, so `canonicalize` gives every position one spelling — otherwise Left/Right
  stalls on duplicates.
- **Implicit multiplication is preserved, not normalised.** `2x` stays `2x`; an explicit `*`
  is only written where leaving it out would merge two tokens (`xy`, `23`, `x2`).
- **Deleting back out of a structure unwraps it** (`b/` → `b`), because losing the numerator
  to a stray Backspace is the silent data loss a maths editor must never commit.
- **`hasEmptySlot` blocks the commit.** `b/` and `1()` have no Calcpad spelling and would
  re-parse as something else, so the editor holds the line open and says so.
- Operators only the engine parses are offered — no `±`, no bare `%`, `*`/`-` not `·`/`−`.

## UI (`calcpad-web/src/live-display/`)

- `CalcpadMathMlEditor.vue` — the surface. Renders MathML natively (browsers typeset it, no
  math library), draws its own caret from a DOM Range, uses the native selection for the
  highlight, maps clicks via `caretRangeFromPoint` + `data-path`. Accessibility: `role=textbox`,
  `aria-label`, and an `aria-live` status announcing the Calcpad text, the caret position and
  the error count. Keyboard: arrows (Shift extends), Up/Down move between structural slots,
  Home/End, Backspace/Delete, `/ ^ _ (` build structures, Enter applies, Esc reverts.
- `CalcpadLiveDisplay.vue` — a persisted **Graphical** checkbox (default **off**) in the editor
  panel, disabled with a reason when the line is not representable. Per-row engine errors come
  from the same `/convert` pass (`convertLines` now returns `{ lines, errors }`), so validation
  needs no extra request; the editing row's diagnostics follow the live preview.
- The palette is routed to the editor's caret in graphical mode (structure/call/glyph mapping).

## Fixed along the way

- `AppInstance` (`calcpad-web/src/editor/app-instance.ts`) was missing the live-display members
  `main.ts` uses — a real gap the new typecheck surfaced.
- Two `InsertItem` interfaces exist (`types/snippets` requires `description`, `vue/types` does
  not). `snippet-insert.ts` now takes a structural `SnippetSource`, which both satisfy.
- `vue-tsc` added to `calcpad-web` with an `npm run typecheck` script — templates were never
  typechecked before.

## Verification

`tsc` clean; **117 tests pass** (38 bridge + 30 caret + 13 shape + 21 palette + 6 split + 9
pre-existing); `vue-tsc` clean; `vite build` clean (1201 modules). Build to a scratch
`--outDir` — emptying `dist/` trips the sandbox bulk-delete guard.

**Not verified:** the browser interaction itself (caret geometry, pointer mapping, native
selection) — that needs the .NET server and a real browser.

## Still open

- Matrix literals (`[...]`) are declined by the bridge; the existing per-cell grid covers them.
- Per-region undo lives in Monaco, not in the graphical surface.

# 2026-10-07 (later still) — Click-to-edit on the rendered row

The resting (not-yet-editing) live row showed a *picture*: server HTML with no `data-path`, so a
click on it could not be mapped to the AST. Instead of tagging the server output, the click's
**viewport point is captured and replayed** against the editing surface once it renders — the
surface is the only place the tree carries `data-path`. The resting row keeps its evaluated
result; the caret still lands under the pointer.

## Core (`calcpad-frontend/src/mathml/`, pure + tested)

- `hit-test.ts` — `anchorFromDomPoint(root, { x, y })` / `anchorForClick`. Resolves the nearest
  tagged ancestor's `data-path`, then: TEXT_NODE inside a token → `char` anchor (clamped to the
  token length, so a click past the glyph lands at its end); empty element → `gap`; otherwise a
  canonicalized `gap`. `anchorForClick` falls back to `firstAnchor(root)` so the caller never
  gets `null`. Pure — testable with jsdom, no browser.
- `line-model.ts` — per-line memo (`lineEditorModel(source)`, 256-entry insertion-order cache;
  `clearLineEditorCache()`), plus `partialTypesetMarkup(source)` which typesets **mid-keystroke**
  input by trimming trailing dangling operators/open structures until a prefix parses. A
  `UNSUPPORTED_CONSTRUCT = /['"[\]{}#$]/` early bail keeps bracket/quote/hash lines from
  producing a misleading half-render (`M = [1; 2` → `''`, not `M`).

## UI

- `CalcpadMathMlEditor.vue`: `anchorFromPoint` now delegates to the shared `anchorForClick`;
  added `tokenSpanAt`, pointer **drag-selection** (`onPointerMove`/`endDrag`), double-click
  (`event.detail >= 2`) token selection, and `defineExpose({ applyPalette, focus, seekAnchor,
  seekPoint })`. `seekPoint(x, y)` focuses then places the caret at the mapped point.
  `.mathml-render { user-select: none; }` so the browser's selection never fights the custom caret.
- `CalcpadLiveDisplay.vue`: `onRowClick` — matrix cell → focus that cell field; click on
  `.live-line-num` → `emit('navigate', …)`; already-open row → no-op; otherwise
  `openEditor(index, { x: event.clientX, y: event.clientY })`, and in graphical mode the stored
  `pendingPoint` is replayed via `seekPoint` on the next tick. `rowHtml` returns `previewHtml`
  once the debounced result is ready, else `partialTypesetMarkup(editable)` — a **local typeset
  with zero latency**, later overridden by the server result so evaluation stays single-source.
- `.live-row.editable:hover` shows a focus-blue outline, `cursor: text` and a `✎` hint;
  the line number becomes a `role="button"` jump target.

## Verification

`tsc` clean; **134 tests pass** (117 + 17 new hit-test/line-model); `vue-tsc` clean; `vite build`
clean (22.4 s). Build to a scratch `--outDir` — emptying `dist/` trips the sandbox bulk-delete
guard.

End-to-end against the running server: `data-source-line` is present on every `<p id="line-N">`
and maps 1:1 to source lines. Launching the server needs
`cmd //c "start /b Calcpad.Server.exe --urls http://127.0.0.1:9420 > artifacts/srv.log"` —

`includeLineAnchors`) is the endpoint the live pane uses.

**Not verified:** the pointer geometry itself (does the caret land visually under the cursor) —
that needs a real browser.
